# Visualizer: moved to its own project, Particle Accelerator

**2026-10-03, the owner:** the visualizer planned here is now a project of its own, **Particle Accelerator** ([github.com/AfterDuskAu/ParticleAccelerator](https://github.com/AfterDuskAu/ParticleAccelerator)). It's built and used on its own first. When it's ready, Music Organizer adds it as a Swift package. The full plan, the visuals, the quality tiers and the measurements live there:

- `docs/PLAN.md`: the roadmap, and why it's built on Apple's Metal rather than Unreal Engine
- `docs/VISUALS.md`: one card per reference picture
- `docs/OUTPUT.md`: quality tiers from the 2019 iMac to a Mac Studio, with measurements
- `docs/INTEGRATION.md`: exactly how Music Organizer adds it

## Done early, on 2026-10-04, at the owner's request

The owner asked for Visualizers 5, 7 and 8 in the app now, before Particle Accelerator's 1.0, with Visualizer 7 as the standard one.

1. **The package is in `app/Package.swift`,** used by the `MusicOrganizer` target only. It's pinned to one commit of Particle Accelerator (there's no 1.0.0 to pin yet), so a change over there never arrives by itself. To take a newer one: change the commit in `app/Package.swift`, run `swift package resolve` in `app/`, and commit `Package.resolved` with it.
2. **The Local Visualizer's switch is Song | Video | Visualizer.** Visualizer plays the song itself and shows the chosen visual where the cover would be, in the video's shape. A video is still a video.
3. **Settings → Play Options → Custom Visualizer** has the two rows that were waiting there: which visualizer (5, 7 or 8; 7 until another is chosen), and whether it takes the cover's place (No until it's turned on). The page's switch changes the second only for now, like the lyrics button.
4. **The listener is given the app's player the first time a visualizer is wanted,** and keeps it until the app is closed: when the app opens, if Settings says to use the visualizer, and otherwise when the page is first switched to it. That's later than Particle Accelerator's `docs/INTEGRATION.md` advises (always when the app starts), so that an app whose owner never uses a visualizer plays exactly as before. The cost: switching to the visualizer for the first time in the middle of a song stops the song for about half a second, once.
   - **Never on an output with a long delay** (2026-10-05). While the Mac's sound goes to an AirPlay device, which holds two seconds of sound, the listener is taken off and the visual's place says why: listening there made the song skip every six seconds (measured; `docs/CHANGELOG.md`). It's put back when the sound returns to the speakers, headphones or a wired output.

5. **They're drawn at Medium quality** unless another is chosen (Settings → Play Options → Custom Visualizer → Quality, since 2026-10-05: Auto, Low, Medium, High, Ultra). Medium, not Auto, is the standard because the owner tuned the three at Medium; and on the 2019 iMac Auto still means High, where Visualizer 8 as the owner has it takes about 18 ms a frame (60 frames a second allows 16.7) against 4.5 at Medium. Particle Accelerator's `docs/OUTPUT.md` has the measurements.
6. **It can have the whole screen, like a video** (2026-10-05, the owner: "just like video"): a Full Screen button under it and a double click on it, the same controls, and the song's lyrics in a column beside it when Settings → Play Options → Show lyrics in full screen says so. It fills what it's given there. A visualizer switched on only for now stays for as long as it has the screen.

Each visual shows as Particle Accelerator's library has it (its standard). The owner's own looks for the three, which had been kept only in the Particle Accelerator app's settings, were written into that library as its standards the same day, so they arrive with the package. Nothing about a visual is changed or kept in Music Organizer.

## Still to do, when Particle Accelerator reaches 1.0

1. Pin its version (`from: "1.0.0"`) in place of the commit, and use its 1.0 view, which takes the player and the song's cover.
2. Put the library's settings panel in Settings, and keep its settings with the app's own (UserDefaults).
3. Offer every finished visual, not three.
4. Make Auto the standard quality, once Auto adapts to what the Mac can hold.
5. Let the visualizer follow the music over AirPlay too, if Particle Accelerator gets a way of hearing it that doesn't put a tap on the player.

Nothing else changes: the visualizer only listens to the player, and writes no files. The app's rule that it never writes inside the library is untouched.

Particle Accelerator is public on GitHub (github.com/AfterDuskAu/ParticleAccelerator, since 2026-10-03), so this repo's CI can fetch it.
